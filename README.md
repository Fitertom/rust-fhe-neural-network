# PPNN (Privacy-Preserving Neural Network)

**PPNN** — это полная implementation (с нуля, на Rust) системы распознавания рукописных цифр, работающая поверх гомоморфного шифрования (FHE).

Сервер **никогда** не видит цифру, которую вы нарисовали. Он получает зашифрованные пиксели, производит вычисления (матричное умножение + активация через bootstrapping) и возвращает зашифрованный результат. Только вы (клиент в браузере) можете расшифровать ответ.

## 🏗 Архитектура

Проект реализует схему **TFHE (Torus Fully Homomorphic Encryption)** с программируемым бутстрэппингом (Programmable Bootstrapping) для вычисления нелинейных функций (ReLU/Square).

### Компоненты
1.  **LWE (Learning With Errors)** (`src/lwe.rs`): Базовый криптографический примитив. Шифрует скалярные значения.
2.  **Bootstrapping** (`src/bootstrap.rs`): Ключевая часть TFHE. Позволяет:
    *   Уменьшить шум в шифротексте (чтобы можно было продолжать вычисления).
    *   Одновременно вычислить нелинейную функцию (LUT) над данными.
3.  **Neural Network** (`src/nn.rs`): Двухслойная сеть (784 -> 32 -> 10).
    *   Обучается на чистых данных (Rust `f64`).
    *   Квантуется в целые числа (`u64`) для FHE.
    *   Инференс выполняется гомоморфно (`src/encrypted_inference.rs`).
4.  **Server** (`src/server.rs`): Axum backend, принимающий шифротексты по HTTP.
5.  **Client** (`static/index.html`): Vanilla JS фронтенд. Реализует шифрование/дешифрование LWE прямо в браузере (через `BigInt`).

## 🛠 История разработки и решенные проблемы

В процессе создания мы столкнулись с рядом серьезных криптографических и инженерных проблем. Вот хроника их решения, сохраненная для истории.

### 1. Переполнение u32 (The "Overflow" Crisis)
Изначально вся криптография была реализована на `u32` (Q=2^32). Это работало для игрушечных примеров, но при запуске реальной нейросети мы столкнулись с переполнением.
*   **Проблема**: При матричном умножении сумма произведений `Σ(a_i * w_i)` превышала `u32::MAX`, разрушая шифротекст. Шум рос слишком быстро.
*   **Решение**: Полная миграция на **u64**.
    *   `Q` (модуль шифротекста) увеличен до `2^64`.
    *   `T` (модуль открытого текста) увеличен до `2^20` (было 2^16).
    *   `Δ` (scaling factor) пересчитан как `2^64 / 2^20 = 2^44`.
    *   Это дало огромный запас по шуму и предотвратило переполнения.

### 2. Точность квантизации
После перехода на u64 точность сети на зашифрованных данных упала до 10% (random guess).
*   **Проблема**: Параметры квантизации были слишком агрессивными. `INPUT_SCALE=3` означал всего 4 градации серого.
*   **Решение**:
    *   Увеличили `INPUT_SCALE` до **15** (16 градаций яркости).
    *   Увеличили `WEIGHT_BOUND` (диапазон весов) с 10 до **15**.
    *   Увеличили `HIDDEN_SCALE` (промежуточная точность) со 100 до **1000**.
    *   Это вернуло точность распознавания к >90%.

### 3. Баг знаковой интерпретации в JS (The "1 vs 4" Bug)
Сеть уверенно предсказывала "4" вместо "1", хотя на сервере логиты были верными.
*   **Проблема**: В LWE арифметика модульная. Число `T-1` (огромное положительное unsigned) на самом деле означает `-1` (маленькое отрицательное signed). JavaScript (`BigInt` и стандартная математика) считал `1,048,575` самым большим числом.
*   **Решение**:
    *   В `index.html` добавлена проверка: если `x >= T/2`, то интерпретировать как `x - T` (отрицательное).
    *   Теперь Argmax и отрисовка графиков (confidence bars) работают корректно.

### 4. Сериализация u64 в JSON
*   **Проблема**: JavaScript `Number` (f64) не может точно представить `u64` значения больше 2^53. Ключи и шифротексты искажались при передаче.
*   **Решение**: Все `u64` поля в API (`LweParams`, `Ciphertext`, `SecretKey`) передаются как **строки** (`String`). Клиент парсит их в `BigInt`.

## 🚀 Запуск

Для работы требуется **Rust** и установленный тулчейн.

### Режимы работы

1.  **Полный цикл (по умолчанию)**
    Обучает сеть на системных шрифтах + ваших рисунках, затем запускает сервер.
    ```bash
    cargo run
    ```

2.  **Только обучение (System + Custom)**
    Генерирует датасет, обучает модель, сохраняет в `model_weights.json`.
    ```bash
    cargo run -- train
    ```

3.  **Обучение только на своих данных**
    Идеально для быстрой донастройки под свой почерк.
    ```bash
    cargo run -- train_only_my
    ```

4.  **Запуск сервера**
    Запускает веб-интерфейс на `http://localhost:3000` с уже обученной моделью.
    ```bash
    cargo run -- serve
    ```

### Как добавить свои данные?
1. Запустите сервер.
2. Рисуйте цифры во вкладке "Collect Data".
3. Данные сохраняются в `static/my_assets/`.
4. Перезапустите обучение (`cargo run -- train_only_my`), чтобы сеть выучила ваш почерк.

## 📚 Технологии

*   **Rust**: Core logic, multithreading (`rayon`), HTTP server (`axum`).
*   **TFHE/LWE**: Full custom implementation of crypto logic.
*   **BigInt**: Client-side cryptography in pure JavaScript.
*   **Neural Network**: Custom `Vec<f64>` / `Vec<u64>` implementation (no Torch/TensorFlow dependencies).
